📋 OrangeHRM Open Source Demo — Manual Software Test Plan & Test Design Project📌 1. Project OverviewThis repository contains a structured, end-to-end Manual Software Testing Documentation Portfolio centered on the publicly accessible OrangeHRM Open Source Demo Human Resource Management System (HRMS).In practical software environments, QA professionals often encounter applications lacking formal Business Requirement Documents (BRDs) or user stories. This project illustrates how to establish a formal test plan, infer expected behaviors from standard UI/UX design patterns, and produce robust, production-grade test cases utilizing foundational black-box test design techniques.Note on Project Status:This project represents a formal test planning, test case authoring, and defect process modeling project. Test cases are prepared with status marked as Not Recorded / Not Run to maintain complete professional authenticity. No executed defects, pass/fail metrics, or claims regarding the underlying application's production stability are asserted.🎯 2. ObjectivesHRMS Workflow Understanding: Map out core workflows common to Human Resource Management systems (authentication, session control, user management, and employee records).Test Case Engineering: Develop modular, repeatable manual test cases with clear preconditions, numbered procedural steps, defined test data, and verifiable expected outcomes.Application of Test Design Techniques: Systematically apply formal black-box methodologies such as Boundary Value Analysis (BVA) and Equivalence Partitioning (EP).Defect Lifecycle Architecture: Establish a clear, standard defect reporting format to facilitate immediate, actionable bug tracking upon test execution.Risk & Scope Management: Define strict in-scope/out-of-scope parameters to optimize testing efficiency within a shared demo environment.🔍 3. Test Design Techniques AppliedTo ensure comprehensive test coverage without redundant test cases, specific black-box methodologies were applied:Boundary Value Analysis (BVA):Targets values at the extreme limits of input ranges ($Min - 1$, $Min$, $Max$, $Max + 1$).Example: If an employee name field permits up to 30 characters, cases test lengths of 29, 30, and 31 characters.Equivalence Partitioning (EP):Divides input domain data into valid and invalid partitions treated uniformly by the application.Example: Separating input classes into empty strings, valid alphanumeric strings, and invalid special-character strings.Decision Table Testing:Maps out complex business logic combinations (e.g., [Valid User + Valid Pass], [Valid User + Invalid Pass], [Invalid User + Valid Pass], [Invalid User + Invalid Pass]).State Transition Testing:Tracks system states across a sequential user path (e.g., Unauthenticated State $\rightarrow$ Authenticated Session $\rightarrow$ Session Timeout / Logged Out).Error Guessing:Leverages QA intuition to predict common user blunders (e.g., spaces-only inputs, copy-pasting excessive strings).📝 6.
